> 状态：讨论稿，按需求逐步调整。本文描述目标、接口边界和验收标准，不代表功能已经实现。
>

> 新后台项目：`D:\代码\DigiwiseStudio-Admin-Java`

## 1. 当前 IDE 开发范围

本阶段只做以下四项，均以新版 RuoYi 后台的真实接口为准：

1. **账号登录**：登录、退出、登录态恢复、会话失效处理。
2. **模板列表读取与渲染**：读取后台返回的全部可见模板，并全部渲染到 IDE 模板界面。
3. **模板下载与创建项目**：用户选择模板后，将对应的远程模板下载到用户指定目录，校验后创建并打开本地项目。
4. **IDE 自动更新**：检查版本、下载更新包、校验、安装并重启。

本阶段不使用 Mock API、不保留旧接口兼容逻辑，也不以静态示例数据作为联调结果。后台未提供真实接口时，功能保持待联调，不用假数据补齐页面。

以下内容移出当前开发范围，后续单独排期：

- 用户云存储、个人空间、配额、云文件管理；
- 型号与 BSP 管理及下载；
- MCP 后台策略管理；
- 邮箱注册、限时试用、授权码及企业席位；
- 迪太云统一认证桥接；
- 后台管理端本身的菜单、角色和业务实现。

这里的“去掉云存储”指 IDE 不建设用户云盘。模板文件和安装包仍属于后台资源，由后台统一管理；IDE 不接收 OSS AccessKey，也不直接操作 OSS。

## 2. 总体结构

```text
DigiwiseStudio IDE
├── 渲染进程：登录页、模板列表、模板向导、更新提示
├── Electron 主进程：会话、网络请求、目录选择、下载、校验、更新安装
└── 受控 IPC：渲染进程不直接保存 Token 或访问文件下载凭据
                 │
                 ▼
          Digiwise IDE Public API
                 │
                 ▼
          RuoYi Spring Boot 3 后台
          ├── IDE 登录接口
          ├── 已发布模板接口
          ├── 模板文件下载接口
          └── IDE 版本更新接口
```

IDE 只调用后台提供的 Public API，不调用 RuoYi 管理端接口（如 `/login`、`/system/**`），不把管理端 Token 当作 IDE Token 使用。

### 3.1 代码组织原则

- 页面只负责展示和交互，不拼接服务地址，不持久化 Token，不直接访问远程文件。
- Electron 主进程统一负责会话、网络请求、文件下载、目录操作和更新安装。
- 账号、模板、项目创建、更新分别维护适配模块，共用 API 地址、错误结构、请求日志和 IPC 类型。
- API 地址通过开发环境和正式环境配置注入，禁止把正式地址硬编码到业务页面。
- 旧 `studio-admin`、旧网关和旧账号接口不作为新版实现依据。

## 4. 账号登录

### 4.1 本阶段范围

本阶段只实现已有账号的登录和会话管理，不扩展注册、试用或授权码业务。登录成功后，IDE 获取用户身份及可用状态，用于后续模板列表和下载请求。

### 4.2 已确认接口

后台已提交 `D:\代码\DigiwiseStudio-Admin-Java\backend\doc\api\ide-public-api.yaml`。账号模块按以下契约实现：

```http
GET  /api/ide/v1/auth/captcha
POST /api/ide/v1/auth/login
GET  /api/ide/v1/auth/me
POST /api/ide/v1/auth/logout
```

登录请求使用 `username`、`password`，验证码启用时追加 `captchaCode` 和 `captchaUuid`。成功响应为 `code: OK`，用户和 Token 位于 `data`；失败必须使用 HTTP 错误状态和契约中的字符串错误码。IDE 使用 `Authorization: Bearer <token>`，不直接调用管理端登录接口。

### 4.3 客户端行为

- 未登录或会话未通过服务端校验时，IDE 显示不可关闭的登录门禁，不加载项目工作区；登录成功后才恢复已打开项目和 IDE 操作。
- 登录成功后只在 Electron 主进程保存会话；优先使用系统安全存储，安全存储不可用时不明文持久化长期凭据。
- 验证码由后台签发，IDE 不绕过验证码策略；验证码启用时支持图片展示、刷新和错误后重新获取。
- 应用启动时尝试恢复会话；恢复失败则回到登录页，并清理失效会话。
- 处理账号不存在、密码错误、账号停用、Token 过期、无权限和后台不可用等状态。
- 退出登录时清理本地 Token、用户信息和依赖会话的缓存。
- 未登录时模板列表、模板下载和需要鉴权的更新操作不能伪造成功结果。

## 5. 模板列表与全量渲染

### 5.1 数据来源

后台负责上传模板文件、封面和元数据，负责发布、下架及版本管理。IDE 只读取后台返回的模板列表，不维护另一套“内置在线模板目录”。

```text
后台上传并发布模板
        ↓
IDE 请求当前用户可见的模板列表
        ↓
IDE 将接口返回的全部模板逐项渲染
        ↓
用户选择一个模板进入创建项目流程
```

“全部渲染”具体指：

- 后台返回多少条，IDE 就展示多少条，不擅自截断、隐藏或替换成示例数据。
- 若后台采用分页，IDE 必须按契约加载全部页面后再完成列表展示，或明确显示分页而不能静默只展示第一页。
- 搜索和筛选只作用于已读取的数据；不能因为客户端暂未识别某个分类就丢弃该模板。
- 模板字段缺失时显示可用的降级文本，并保留该模板卡片；不能因单个字段异常导致整个列表消失。

### 5.2 建议接口和字段

```http
GET /api/ide/v1/templates
GET /api/ide/v1/templates/{templateId}
GET /api/ide/v1/templates/{templateId}/download
```

新建页模板卡片直接读取 `GET /api/ide/v1/templates?page=1&pageSize=100`，使用 IDE Bearer Token。列表按 `data.page`、`data.pageSize` 和 `data.total` 继续请求，直到取得全部 `data.items`；分类筛选和名称搜索在客户端对完整列表执行。禁止用静态模板卡片补齐接口结果。

卡片字段映射：`name` 为名称、`coverUrl` 为封面、`description` 为描述、`category` 为筛选分类、`projectType` 为项目类型、`version` 为当前发布版本。`coverUrl` 为空或加载失败时显示通用占位图，单张封面失败不得隐藏模板。接口缺少分辨率字段时，页面显示“由模板文件确定”，不把 IDE 默认值当成模板实际分辨率。

列表和创建下载分别使用独立 IPC 适配。Token 只保留在 Electron 主进程；渲染进程不能直接访问 Public API 或 OSS。下载使用模板 ID 和列表提供的明确版本号，不静默切换到其他版本。当前列表只展示后台提供的最新发布版本；后续若产品要求选择历史版本，再接入详情接口的版本列表。

列表或详情至少需要能够表达：

```text
id、name、description、category、coverUrl 或 coverId
version、fileName、fileSize、sha256
projectType、lvglVersion、publishedAt
```

建议后台只返回已发布且当前用户可访问的记录；若接口同时返回状态字段，IDE 仍以服务端返回的可下载结果为准。

### 5.3 页面状态

模板页面必须覆盖以下状态：

- 首次加载：显示加载状态，禁止把加载中的空列表当成“没有模板”；
- 成功：渲染全部返回项；
- 空列表：明确显示“暂无可用模板”；
- 网络失败、401、403、5xx：显示中文错误和重试入口；
- 封面失败：模板信息仍可显示，使用统一占位样式，不影响其他模板；
- 列表刷新：不覆盖用户当前已选模板，除非该模板已经被后台确认不可用。

## 6. 模板下载与创建本地项目

### 6.1 用户流程

```text
登录
  ↓
读取并展示全部模板
  ↓
用户选择模板和版本
  ↓
填写项目名称，选择本地目标目录
  ↓
下载选定的远程模板版本
  ↓
校验文件大小和 SHA-256
  ↓
安全解压或复制到目标目录
  ↓
检查项目入口并打开本地项目
```

建议将用户选择的目录作为项目根目录，最终路径为“用户目录 + 项目名称”；如果后台或现有向导采用其他路径规则，需在实施前固定并写入契约，不能由不同页面各自解释。

### 6.2 必须保证的行为

- 下载请求绑定模板 ID 和明确版本，不能下载“当前最新”后再悄悄替换用户选择。
- 下载到临时文件，完成大小和 SHA-256 校验后再写入目标目录。
- 目标目录或目标项目已存在时停止操作并提示用户，禁止静默覆盖。
- 下载取消、网络中断、校验失败或解压失败时清理临时文件，不留下半成品项目。
- 压缩包解压必须防止路径穿越；最终目录应检查 `.eez-project` 或后台约定的项目入口。
- 下载进度和失败原因在界面中可见；当前通过进度阶段与字节数显示，尚未实现速度及下载取消。
- 创建成功后复用现有项目打开流程，不新增一套平行项目启动器。

契约支持单个 `.eez-project` 文件和 ZIP 两种格式。ZIP 必须恰好包含一个 `.eez-project`；拒绝路径穿越、符号链接、可执行脚本/二进制及超过解压上限的内容，绝不执行 `post.js`。

### 6.3 与现有代码衔接

现有 `packages/project-editor/project/ui/Wizard.tsx` 已包含项目名称、位置选择和本地项目创建流程。实施时应增加后台模板适配层，复用向导的本地创建能力，并把远程下载、校验和解压放到 Electron 主进程，不在渲染进程直接写入项目文件。

## 7. IDE 自动更新

### 7.1 实现原则

复用现有更新代码，不新建第二套更新器：

- `packages/main/update-discovery.ts`：版本检查和不可变更新源发现；
- `packages/main/main.ts`：`electron-updater` 初始化、下载、安装和重启。

新版只需把更新源和环境配置切换到后台约定的 Public API 或官方更新源。

### 7.2 建议接口

```http
GET /api/ide/v1/releases/check?channel=stable&version=<currentVersion>&platform=<platform>&arch=<arch>
GET /api/ide/v1/releases/{releaseId}/manifest
GET /api/ide/v1/releases/{releaseId}/download
```

更新清单至少需要表达：版本号、构建号、渠道、平台、架构、是否强制更新、安装包地址、文件大小、SHA-512 或签名信息、发布时间和更新说明。后台返回的下载地址必须是 HTTPS 或受更新器信任的本地源。

### 7.3 客户端行为

- 应用启动后检查一次，并提供手动检查入口；检查失败不阻断 IDE 启动。
- 仅当远程版本高于当前版本且渠道、平台、架构匹配时提示更新。
- 显示版本号、更新说明、下载进度、安装失败和重试结果。
- 下载后完成签名/哈希校验，再交给现有更新器安装；不执行未经校验的安装包。
- 用户确认后安装并重启；强制更新策略由后台清单和产品规则确定。
- 开发环境只做本地更新源、清单和失败场景验证，不触发 Dev Release 或生产发布。

## 8. 接口与环境规范

- 统一使用 `/api/ide/v1` 作为 IDE Public API 前缀；`v1` 是接口版本，不是环境名称。
- 开发、测试、正式环境分别配置 API 地址，例如 `DIGIWISE_IDE_API_BASE_URL`，正式环境使用 HTTPS；具体域名由后台侧提供。
- RuoYi 管理前端的 `/dev-api`、`/prod-api` 仅属于管理端代理配置，不能直接当作 IDE API 地址。
- 后台应提供独立的 IDE Public API 路由和 OpenAPI 契约，建议放在 `backend/doc/api/ide-public-api.yaml`。
- JSON 接口统一约定响应结构、错误码、请求号、时间格式和分页；文件下载单独约定 `Content-Length`、`Content-Type`、`ETag` 或校验字段。
- 建议至少区分 `401` 未登录、`403` 无权限、`404` 资源不存在、`409` 目标冲突、`422` 参数无效、`429` 限流和 `5xx` 后台错误。
- IDE 不保存后台密钥、OSS AccessKey 或管理端 Token；模板和安装包的实际存储位置对 IDE 透明。
- 现有 `packages/main/digiwise-auth.ts` 中的旧网关地址和旧协议不作为新版依据，待新版契约确认后替换。
